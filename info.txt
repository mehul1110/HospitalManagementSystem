Hospital Management System (Spring Boot + JWT)
1. Project Title
Hospital Management System using Spring Boot and JWT Authentication

2. Project Overview
This project is a small and practical Hospital Management System made for student implementation.
The project is intentionally kept simple so that the main focus stays on:
understanding Spring Boot project structure
learning JWT authentication
securing APIs
performing CRUD operations
building a backend project in a clean and practical way
This is not a large hospital project. It is a mini-project for practice.

3. Main Goal of the Project
The goal of this project is to create a backend application where:
a user can register and log in
JWT token is generated after login
secured APIs can be accessed using the token
patient records can be created, viewed, updated, and deleted
This makes the project small, easy to understand, and good for hands-on implementation.

4. Modules in the Project
This project has only 2 modules.
4.1 Auth Module
This module is used for:
user registration
user login
JWT token generation
JWT token validation
securing APIs
4.2 Patient Module
This module is used for:
adding a patient
viewing all patients
viewing one patient by id
updating patient details
deleting a patient

5. Why This Scope Is Good
This project scope is good because:
it is small
it is easy for students to build
JWT implementation is included properly
CRUD is included properly
security is included
it is enough for demo, viva, and practical understanding
This version avoids unnecessary complexity.

7. Purpose of Each Package and Class
7.1 config package
This package contains the JWT and security-related classes.
SecurityConfig.java
Used to configure Spring Security.
Main work:
disable CSRF for API testing
allow register and login APIs without token
secure patient APIs
set session policy as stateless
add JWT filter before username-password authentication filter
JwtAuthenticationFilter.java
Used to check every incoming request.
Main work:
read JWT token from Authorization header
validate the token
extract username/email from token
set authentication in Spring Security context
JwtService.java
Used for all JWT-related operations.
Main work:
generate token
extract username from token
validate token
check token expiry

7.2 controller package
This package contains API endpoints.
AuthController.java
Handles authentication APIs.
Main work:
register user
login user
return JWT token after login
PatientController.java
Handles patient CRUD APIs.

add patient
get all patients

12. API Endpoints
12.1 Auth APIs
Register User
POST /api/auth/register
Sample Request:
{
  "name": "Admin User",
  "email": "admin@gmail.com",
  "password": "Admin@123"
}

Sample Response:
{
  "message": "User registered successfully"
}

Login User
POST /api/auth/login
Sample Request:
{
  "email": "admin@gmail.com",
  "password": "Admin@123"
}

Sample Response:
{
  "token": "your_jwt_token_here",
  "message": "Login successful"
}


12.2 Patient APIs
All patient APIs must be secured.
Add Patient
POST /api/patients
Sample Request:
{
  "name": "Rahul Kumar",
  "age": 27,
  "gender": "Male",
  "disease": "Fever",
  "address": "Chennai",
  "phoneNumber": "9876543210"
}

Get All Patients
GET /api/patients
Get Patient By Id
GET /api/patients/{id}
Update Patient
PUT /api/patients/{id}
Sample Request:
{
  "name": "Rahul Kumar",
  "age": 28,
  "gender": "Male",
  "disease": "Viral Fever",
  "address": "Chennai",
  "phoneNumber": "9876543210"
}

Delete Patient
DELETE /api/patients/{id}

13. Authorization Header Format
To access secured APIs, the JWT token must be sent in the request header.
Authorization: Bearer <your_token>


14. Project Flow
14.1 Registration Flow
user sends name, email, and password
request reaches AuthController
AuthService checks whether user already exists
password is encoded
user is saved in database
success message is returned
14.2 Login Flow
user sends email and password
request reaches AuthController
AuthService verifies credentials
if credentials are correct, JWT token is generated
token is sent in response
14.3 Access Secured API Flow
user logs in and gets JWT token
user sends token in Authorization header
JwtAuthenticationFilter intercepts the request
token is validated using JwtService
if token is valid, request is allowed
request reaches PatientController
14.4 Patient CRUD Flow
authenticated user calls patient API
request reaches PatientController
controller calls PatientService
service performs logic
repository interacts with database
response is returned
